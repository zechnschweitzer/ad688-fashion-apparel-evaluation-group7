Market Overview

A quick look at the apparel and fashion analytics market captured in our filtered data. After applying the NAICS 458 filter and checking a list of known apparel and fashion employers, we ended up with 19 verified job postings.

Since the sample is intentionally narrow, the results are best used to understand this specific set of postings. They should not be treated as a representation of the overall analytics job market.

Functional Role Segmentation

Individual job titles in the sample are highly fragmented, with many titles appearing only once. To identify broader hiring patterns, the titles are grouped into functional categories based on the primary focus of each role. This provides a more interpretable view of the types of analytics work represented in the selected apparel and fashion job postings.

Show code 
import plotly.express as px


def classify_role(title):
    title = str(title).lower()

    if any(keyword in title for keyword in [
        "business intelligence",
        "data analyst",
        "data governance",
        "data analytics"
    ]):
        return "BI / Data Analytics"

    elif any(keyword in title for keyword in [
        "operations",
        "operational",
        "region operations"
    ]):
        return "Operations Analytics"

    elif any(keyword in title for keyword in [
        "marketing",
        "media",
        "customer",
        "consumer",
        "digital analytics"
    ]):
        return "Marketing / Customer Analytics"

    elif any(keyword in title for keyword in [
        "merchandising",
        "merchandise",
        "ecommerce",
        "e-commerce",
        "retail",
        "wholesale",
        "sales planning"
    ]):
        return "Merchandising / Ecommerce"

    elif any(keyword in title for keyword in [
        "finance",
        "financial",
        "fp&a",
        "strategy",
        "strategic"
    ]):
        return "Finance / Strategy Analytics"

    elif any(keyword in title for keyword in [
        "product",
        "engineering"
    ]):
        return "Product / Engineering Analytics"

    else:
        return "Other Analytics"


# Create broader functional role categories
clean_df["ROLE_SEGMENT"] = clean_df["TITLE_CLEAN"].apply(classify_role)

Marketing and customer analytics follows closely with 5 postings, while merchandising and ecommerce account for 3. Data Completeness Across Key Attributes

Several analytical fields in the job-posting dataset contain substantial missing information. Comparing attribute coverage helps distinguish which findings are supported by most of the sample and which rely on a smaller subset of postings.

Show code 
import pandas as pd
import plotly.express as px

total_postings = len(raw_df)

# Count only clearly identified work-arrangement values.
# Missing and "Unknown" values are treated as unavailable.
work_arrangement_usable = (
    raw_df["REMOTE_TYPE_NAME"].notna()
    & raw_df["REMOTE_TYPE_NAME"]
        .astype(str)
        .str.strip()
        .str.lower()
        .ne("unknown")
).sum()

coverage_data = pd.DataFrame({
    "Attribute": [
        "Job Title",
        "Employer",
        "Location",
        "Observed Salary Range",
        "Minimum Experience",
        "Work Arrangement"
    ],
    "Postings with Usable Data": [
        raw_df["TITLE_CLEAN"].notna().sum(),
        raw_df["COMPANY_CLEAN"].notna().sum(),
        raw_df["LOCATION"].notna().sum(),
        raw_df[["SALARY_FROM", "SALARY_TO"]]
            .notna()
            .all(axis=1)
            .sum(),
        raw_df["MIN_YEARS_EXPERIENCE"].notna().sum(),
        work_arrangement_usable
    ]
})

coverage_data["Coverage Percentage"] = (
    coverage_data["Postings with Usable Data"]
    / total_postings
    * 100
).round(1)

coverage_data = coverage_data.sort_values(
    "Postings with Usable Data",
    ascending=True
)

# print(coverage_data)

fig_coverage = px.bar(
    coverage_data,
    x="Postings with Usable Data",
    y="Attribute",
    orientation="h",
    text="Coverage Percentage",
    template="group7",
    color_discrete_sequence=["#69558E"],
    title="Coverage of Key Job-Posting Attributes"
)

fig_coverage.update_traces(
    texttemplate="%{text:.1f}%",
    textposition="outside"
)

fig_coverage.update_layout(
    title_x=0.5,
    height=450,
    xaxis_title="Number of Postings with Usable Data",
    yaxis_title="Attribute"
)

fig_coverage.update_xaxes(
    dtick=1,
    range=[0, total_postings + 2]
)

fig_coverage.show()

Job title, employer, and location are available for all 19 postings. Experience data is less complete, with usable minimum-experience information for 9 postings. Salary and work-arrangement data are the most limited, with only 4 usable records for each.

This difference in coverage matters when reading the rest of the EDA. The title, employer, and location findings use the full sample, while the salary, experience, and remote-work results come from much smaller subsets. Those smaller sections are still useful, but they should be read with more caution.

Salary Distribution

Salary information is incomplete in the filtered dataset. Only postings with an originally reported salary range are included in this analysis. Missing salaries that were filled during data preparation are excluded so that the results reflect observed compensation information rather than imputed values.

Show code 
import pandas as pd
import plotly.graph_objects as go

salary_df = raw_df.copy()

salary_df["SALARY_FROM"] = pd.to_numeric(
    salary_df["SALARY_FROM"],
    errors="coerce"
)

salary_df["SALARY_TO"] = pd.to_numeric(
    salary_df["SALARY_TO"],
    errors="coerce"
)

salary_observed = salary_df.dropna(
    subset=["SALARY_FROM", "SALARY_TO"]
).copy()

salary_observed["SALARY_MIDPOINT"] = (
    salary_observed["SALARY_FROM"] +
    salary_observed["SALARY_TO"]
) / 2

salary_observed = salary_observed.sort_values(
    "SALARY_MIDPOINT"
).reset_index(drop=True)

# Build base label using title and employer
salary_observed["BASE_LABEL"] = salary_observed.apply(
    lambda row: (
        f"{row['TITLE_CLEAN']} ({row['COMPANY_NAME']})"
        if pd.notna(row.get("COMPANY_NAME"))
        else row["TITLE_CLEAN"]
    ),
    axis=1
)

# Number repeated labels so separate postings remain visible
salary_observed["DUPLICATE_NUMBER"] = (
    salary_observed.groupby("BASE_LABEL").cumcount() + 1
)

salary_observed["DUPLICATE_TOTAL"] = (
    salary_observed.groupby("BASE_LABEL")["BASE_LABEL"].transform("count")
)

salary_observed["LABEL"] = salary_observed.apply(
    lambda row: (
        f"{row['BASE_LABEL']} - Posting {row['DUPLICATE_NUMBER']}"
        if row["DUPLICATE_TOTAL"] > 1
        else row["BASE_LABEL"]
    ),
    axis=1
)

# print(
#     f"Postings with observed salary ranges: "
#     f"{len(salary_observed)} of {len(raw_df)}"
# )

fig = go.Figure()

for _, row in salary_observed.iterrows():

    fig.add_trace(
        go.Scatter(
            x=[
                row["SALARY_FROM"],
                row["SALARY_TO"]
            ],
            y=[
                row["LABEL"],
                row["LABEL"]
            ],
            mode="lines+markers",
            line=dict(width=4),
            marker=dict(size=9),
            showlegend=False,
            hovertemplate=(
                "<b>%{y}</b><br>"
                "Salary: $%{x:,.0f}"
                "<extra></extra>"
            )
        )
    )

fig.update_layout(
    title="Observed Salary Ranges",
    xaxis_title="Annual Salary ($)",
    yaxis_title="",
    height=560,
    margin=dict(
        l=320,
        r=40,
        t=70,
        b=50
    )
)

fig.update_xaxes(
    tickprefix="$",
    tickformat="~s"
)

fig.show()

Only 4 of the 19 postings contain an observed salary range, so the salary findings should be interpreted cautiously. The available postings show variation in both the lower and upper ends of reported compensation, but the small number of observations is not sufficient to characterize salary levels across the full selected apparel and fashion analytics market. The chart therefore presents only compensation that was explicitly reported in the source postings.

Baseline Summary

The market baseline provides a descriptive snapshot of analytics-related opportunities within the selected apparel and fashion industry scope. The final dataset contains 19 verified job postings and shows that analytics work appears across several functional areas, including business intelligence, merchandising, ecommerce, finance, operations, and marketing.

Hiring activity is concentrated among a small group of employers and locations. Vuori and TJX each account for 5 postings, while California and Massachusetts each account for 5 postings. New York and Oregon also represent notable hiring locations within the sample.

Several variables have substantial missing information. Only 4 postings contain observed salary ranges, 9 contain recorded minimum experience requirements, and 4 contain an identifiable work arrangement. These limitations are retained explicitly in the analysis rather than treating imputed or missing values as if they were directly reported by employers.

Overall, the findings should be interpreted as a baseline for this narrowly defined apparel and fashion analytics market rather than as estimates of the broader analytics labor market. The results provide a foundation for the later skill-gap and career-evaluation stages of the project.

## Functional Role Segmentation

Individual job titles in the sample are highly fragmented, with many titles appearing only once. To identify broader hiring patterns, the titles are grouped into functional categories based on the primary focus of each role. This provides a more interpretable view of the types of analytics work represented in the selected apparel and fashion job postings.

```{python}
#| warning: false
#| message: false

import plotly.express as px


def classify_role(title):
    title = str(title).lower()

    if any(keyword in title for keyword in [
        "business intelligence",
        "data analyst",
        "data governance",
        "data analytics"
    ]):
        return "BI / Data Analytics"

    elif any(keyword in title for keyword in [
        "operations",
        "operational",
        "region operations"
    ]):
        return "Operations Analytics"

    elif any(keyword in title for keyword in [
        "marketing",
        "media",
        "customer",
        "consumer",
        "digital analytics"
    ]):
        return "Marketing / Customer Analytics"

    elif any(keyword in title for keyword in [
        "merchandising",
        "merchandise",
        "ecommerce",
        "e-commerce",
        "retail",
        "wholesale",
        "sales planning"
    ]):
        return "Merchandising / Ecommerce"

    elif any(keyword in title for keyword in [
        "finance",
        "financial",
        "fp&a",
        "strategy",
        "strategic"
    ]):
        return "Finance / Strategy Analytics"

    elif any(keyword in title for keyword in [
        "product",
        "engineering"
    ]):
        return "Product / Engineering Analytics"

    else:
        return "Other Analytics"


# Create broader functional role categories
clean_df["ROLE_SEGMENT"] = clean_df["TITLE_CLEAN"].apply(classify_role)

# Count postings within each functional area

    .reset_index()
)

]

# Sort so the horizontal chart reads from smaller to larger values

    ascending=True
)

# Display counts for validation

other_titles = clean_df.loc[

Because the dataset is small and the categories are derived from job-title wording, the results should be interpreted as a descriptive view of the selected postings rather than a standardized representation of the broader industry.

## Data Completeness Across Key Attributes

Several analytical fields in the job-posting dataset contain substantial missing information. Comparing attribute coverage helps distinguish which findings are supported by most of the sample and which rely on a smaller subset of postings.

```{python}
#| warning: false
#| message: false

import pandas as pd
import plotly.express as px

total_postings = len(raw_df)

# Count only clearly identified work-arrangement values.
# Missing and "Unknown" values are treated as unavailable.
work_arrangement_usable = (
    raw_df["REMOTE_TYPE_NAME"].notna()
    & raw_df["REMOTE_TYPE_NAME"]
        .astype(str)
        .str.strip()
        .str.lower()
        .ne("unknown")
).sum()

coverage_data = pd.DataFrame({
    "Attribute": [
        "Job Title",
        "Employer",
        "Location",
        "Observed Salary Range",
        "Minimum Experience",
        "Work Arrangement"
    ],
    "Postings with Usable Data": [
        raw_df["TITLE_CLEAN"].notna().sum(),
        raw_df["COMPANY_CLEAN"].notna().sum(),
        raw_df["LOCATION"].notna().sum(),
        raw_df[["SALARY_FROM", "SALARY_TO"]]
            .notna()
            .all(axis=1)
            .sum(),
        raw_df["MIN_YEARS_EXPERIENCE"].notna().sum(),
        work_arrangement_usable
    ]
})

coverage_data["Coverage Percentage"] = (
    coverage_data["Postings with Usable Data"]
    / total_postings
    * 100
).round(1)

coverage_data = coverage_data.sort_values(
    "Postings with Usable Data",
    ascending=True
)

# print(coverage_data)

fig_coverage = px.bar(
    coverage_data,
    x="Postings with Usable Data",
    y="Attribute",
    orientation="h",
    text="Coverage Percentage",
    template="group7",
    color_discrete_sequence=["#69558E"],
    title="Coverage of Key Job-Posting Attributes"
)

fig_coverage.update_traces(
    texttemplate="%{text:.1f}%",
    textposition="outside"
)

fig_coverage.update_layout(
    title_x=0.5,
    height=450,
    xaxis_title="Number of Postings with Usable Data",
    yaxis_title="Attribute"
)

fig_coverage.update_xaxes(
    dtick=1,
    range=[0, total_postings + 2]
)

fig_coverage.show()
```

Job title, employer, and location are available for all 19 postings. Experience data is less complete, with usable minimum-experience information for 9 postings. Salary and work-arrangement data are the most limited, with only 4 usable records for each.

This difference in coverage matters when reading the rest of the EDA. The title, employer, and location findings use the full sample, while the salary, experience, and remote-work results come from much smaller subsets. Those smaller sections are still useful, but they should be read with more caution.

## Salary Distribution

Salary information is incomplete in the filtered dataset. Only postings with an originally reported salary range are included in this analysis. Missing salaries that were filled during data preparation are excluded so that the results reflect observed compensation information rather than imputed values.

```{python}
import pandas as pd
import plotly.graph_objects as go

salary_df = raw_df.copy()

salary_df["SALARY_FROM"] = pd.to_numeric(
    salary_df["SALARY_FROM"],
    errors="coerce"
)

salary_df["SALARY_TO"] = pd.to_numeric(
    salary_df["SALARY_TO"],
    errors="coerce"
)

salary_observed = salary_df.dropna(
    subset=["SALARY_FROM", "SALARY_TO"]
).copy()

salary_observed["SALARY_MIDPOINT"] = (
    salary_observed["SALARY_FROM"] +
    salary_observed["SALARY_TO"]
) / 2

salary_observed = salary_observed.sort_values(
    "SALARY_MIDPOINT"
).reset_index(drop=True)

# Build base label using title and employer
salary_observed["BASE_LABEL"] = salary_observed.apply(
    lambda row: (
        f"{row['TITLE_CLEAN']} ({row['COMPANY_NAME']})"
        if pd.notna(row.get("COMPANY_NAME"))
        else row["TITLE_CLEAN"]
    ),
    axis=1
)

# Number repeated labels so separate postings remain visible
salary_observed["DUPLICATE_NUMBER"] = (
    salary_observed.groupby("BASE_LABEL").cumcount() + 1
)

salary_observed["DUPLICATE_TOTAL"] = (
    salary_observed.groupby("BASE_LABEL")["BASE_LABEL"].transform("count")
)

salary_observed["LABEL"] = salary_observed.apply(
    lambda row: (
        f"{row['BASE_LABEL']} - Posting {row['DUPLICATE_NUMBER']}"
        if row["DUPLICATE_TOTAL"] > 1
        else row["BASE_LABEL"]
    ),
    axis=1
)

# print(
#     f"Postings with observed salary ranges: "
#     f"{len(salary_observed)} of {len(raw_df)}"
# )

fig = go.Figure()

for _, row in salary_observed.iterrows():

    fig.add_trace(
        go.Scatter(
            x=[
                row["SALARY_FROM"],
                row["SALARY_TO"]
            ],
            y=[
                row["LABEL"],
                row["LABEL"]
            ],
            mode="lines+markers",
            line=dict(width=4),
            marker=dict(size=9),
            showlegend=False,
            hovertemplate=(
                "<b>%{y}</b><br>"
                "Salary: $%{x:,.0f}"
                "<extra></extra>"
            )
        )
    )

fig.update_layout(
    title="Observed Salary Ranges",
    xaxis_title="Annual Salary ($)",
    yaxis_title="",
    height=560,
    margin=dict(
        l=320,
        r=40,
        t=70,
        b=50
    )
)

fig.update_xaxes(
    tickprefix="$",
    tickformat="~s"
)

fig.show()
```

Only 4 of the 19 postings contain an observed salary range, so the salary findings should be interpreted cautiously. The available postings show variation in both the lower and upper ends of reported compensation, but the small number of observations is not sufficient to characterize salary levels across the full selected apparel and fashion analytics market. The chart therefore presents only compensation that was explicitly reported in the source postings.

## Baseline Summary

The market baseline provides a descriptive snapshot of analytics-related opportunities within the selected apparel and fashion industry scope. The final dataset contains 19 verified job postings and shows that analytics work appears across several functional areas, including business intelligence, merchandising, ecommerce, finance, operations, and marketing.

Hiring activity is concentrated among a small group of employers and locations. Vuori and TJX each account for 5 postings, while California and Massachusetts each account for 5 postings. New York and Oregon also represent notable hiring locations within the sample.

Several variables have substantial missing information. Only 4 postings contain observed salary ranges, 9 contain recorded minimum experience requirements, and 4 contain an identifiable work arrangement. These limitations are retained explicitly in the analysis rather than treating imputed or missing values as if they were directly reported by employers.

Overall, the findings should be interpreted as a baseline for this narrowly defined apparel and fashion analytics market rather than as estimates of the broader analytics labor market. The results provide a foundation for the later skill-gap and career-evaluation stages of the project.
